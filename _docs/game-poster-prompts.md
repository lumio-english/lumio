# Mini-Game Poster Prompts (7 games)

Where these go: each level's "Mini-Game" section on the student dashboard
currently shows one wide banner card (`.sd-game-wide` in student.html) with
a plain CSS gradient background — the exact same gradient used in each
prompt below, so a generated poster will feel like a natural evolution of
the current look, not a mismatched swap. The card is a **wide, landscape
banner** (roughly 4:1, much wider than tall — closer to a website hero
banner than a portrait movie poster), and it always has white text sitting
on top of it (icon, game title, one-line description, a white "Play"
pill button) with a drop-shadow for legibility. Every prompt below asks
for a calmer, less busy passage of the composition (usually the lower or
one side) so that overlay text stays readable without needing a heavy
dark scrim on top of the art — mentioned explicitly in each prompt rather
than left implicit.

Shared style language used in every prompt, matching the platform's
existing character art exactly: **semi-realistic cartoon illustration,
warm and polished (not flat-vector), thick clean outlines, soft
lighting, bright saturated colors, friendly and energetic mood, aimed
at Arabic-speaking students** — young kids for Pre-A/Level 1/Level 2,
early teens for Level 3-6. Landscape orientation, no text or letters
anywhere in the image (the app renders the title/description as real
HTML text on top), no watermark.

## Notes for whoever generates these

- **Save as:** `assets/games/poster-{level}.png` (e.g. `poster-pre-a.png`,
  `poster-level1.png` ... `poster-level6.png`) — matches the level keys
  already used in `GAME_INFO` in student.html, so wiring them in later
  is a one-line change per level (`background-image: url(...)` layered
  over the existing gradient, not a replacement — keeps a graceful
  fallback if an image ever fails to load).
- **Aspect ratio:** aim for roughly 4:1 landscape (e.g. 1600×400 or
  2000×500). The card's exact on-screen height flexes with its text
  content, so err on the side of a wider, shorter image rather than a
  taller one — CSS `background-size: cover` will crop a too-tall image
  awkwardly.
- **Left-third-calm rule:** every prompt above asks for the left third
  of the frame to stay visually calm — that's where the icon, title,
  description, and Play button currently render. If a generation comes
  back with the busiest part of the art on the left, it'll fight with
  the text; regenerate rather than trying to force it to work.
- **Character consistency:** if your image tool supports reference
  images, feed it the existing character PNGs from
  `assets/story/characters/` (young cast: omar, sara, noor, lumi;
  teen cast: the `-teen-` suffixed versions) so the poster's characters
  actually match what students already recognize from the rest of the
  app, rather than generating new, unfamiliar-looking versions of them.
